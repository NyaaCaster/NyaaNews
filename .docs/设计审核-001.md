# 猫猫报纸设计审核

2026-10-26：方案已获用户批准。

## 结论

采用 Python 批处理与 Linux Docker 容器（2026-11-01 起在 macmini 生产部署），容器 cron 按配置时区调度。
RSS/Atom 仅用于候选发现，程序直接获取公开原文。无模型或 MCP 依赖。
来源失败按站点隔离，不能将请求失败记为“没有新闻”。

## 数据流与边界

配置 → RSS/Atom → 候选缓存 → 时间/主题过滤 → 公开正文 → 去重及配额 → Markdown → 持久 outbox → AstrBot。

- 公网下载解析 DNS 后连接固定的已验证公网 IP，逐个检查重定向，TLS 仍校验原始主机。
- Atom 优先 alternate HTML link，禁止把 replies/comments feed 当文章。
- Feed 发布时间与社区提交时间分开处理；精度或时区不明时不伪造。
- 正文抽取保留原文，不用 RSS 摘要充当全文；去除菜单并保留图注。
- 私有来源配置采用显式主题规则，泛技术站不能整站自动归类成图形学或架构。
- 每篇只占一个主主题的每日额度，重跑不重置额度；缺新闻时输出真实缺口。
- SQLite 写事务前做在线快照并校验；文件原子落盘后登记状态，启动时对账孤立文件。
- 网络写入前落盘 submitted，未知结果先远端对账，禁止盲目重传。

## 部署和秘密

应用在 macmini Docker 运行，本机负责研发和构建。实际宿主机数据根目录由私有配置指定，绑定 /data。
配置只读挂载；容器临时目录任务结束清理，异常遗留由下轮持锁后回收。
镜像仅白名单复制代码，不含来源名单、主题、凭据、原文或历史参考资料。

AstrBot 保持现有部署。其数据库写入前仍需服务端快照；本地数据库备份不能替代。
使用专用受限 SSH 入口访问原有服务，密钥只能调用指定知识库的 API/备份，不能执行任意命令或转发端口。
该入口是既有知识库的备份接入辅助程序，不是远程部署 NyaaNews。

## 验证口径

此前 33 篇原型验证只覆盖 RSS、正文下载和落盘；没有目标日过滤，
也有宽泛来源导致的错误分类，不能写成生产批处理已经验收。
历史原件保留在私有 .ref/；产品以日期、主题和正文校验后的结果验收。
满额不是每天成功的条件，允许没有新闻，但不允许拿旧文或无关文补数。

阶段状态与后续工作见开发计划-SSOT.md。

## 实施核验补充（2026-10-26）

已完成本机容器运行、真实 cron 触发及正式归档/入库核验。
宿主机到既有知识库可直连，容器直连局域网超时；容器通过可选 SOCKS5 传输访问同一受信 SSH 主机。
这一环境依赖已写入私有配置及运维说明，未新增宿主机转发服务，也未关闭主机密钥校验。
备份和历史运行记录不自动删除，容量策略保留为运维事项。
连续 3 个真实日的调度观察仍待满期；详见 SSOT，不以模拟 3 日测试替代。

## 0.1.1 正文链路修复核验

标准客户端收到 403 验证页；源级浏览器兼容 HTTP 请求取得原页面。
新增 curl-cffi 锁定依赖，公网地址检查、IP 固定、TLS 校验、逐跳检查和大小/时间限制保留。
22 项测试通过，容器内完成原文落盘、哈希、异步入库、15 块内容、语义检索及重复运行核验。
本轮只修复正文请求，未扩充订阅来源，覆盖方案需与用户讨论后再实施。

## 0.2.0 有序多来源方案

用户已授权每品目扩充 3～5 个公开来源，来源清单仍仅保存在私有配置。
选择来源前检查该品目缺额；逐来源完成原文校验与去重后再选择下一来源，而非先轮询所有来源。
满额后停止后续订阅及正文请求；共享源共用轮询，按品目独立筛选，跨品目不重复占额。
来源全部用尽仍不足时同步实际数量，记录数量缺口；真实请求失败独立保留，不能用数量不足代替失败。
标题级规则用于减少泛技术来源中的普通更新被归类成重大事件；真实样本分类复核在入库前完成。
短订阅列表和站点更新频率仍可能造成目标日缺口，本次不放宽时间窗，也不把摘要当正文。


## 2026-11-01 部署决策修订

用户要求迁往 macmini；此前“不在远端运行采集器”的约束已被本次指令替代。
源端容器先停止，生产只运行一份日调度。数据和备份分别绑定挂载盘业务目录及统一备份目录。
生产 Compose 与开发 Compose 分离，镜像构建推送与生产启动分离。存储未挂载时 restart.py 拒绝部署。
沿用既有受限 AstrBot 网关，生产配置关闭原 Windows 代理依赖，实际连接由迁移验收确认。
