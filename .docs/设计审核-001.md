# 猫猫报纸设计审核

2026-10-26：方案已获用户批准。

## 结论

采用 Python 批处理与本机 Linux Docker 容器，容器 cron 按配置时区调度。
RSS/Atom 仅用于候选发现，程序直接获取公开原文。无模型或 MCP 依赖。
来源失败按站点隔离，不能将请求失败记为“没有新闻”。

## 数据流与边界

配置 → RSS/Atom → 候选缓存 → 时间/主题过滤 → 公开正文 → 去重及配额 → Markdown → 持久 outbox → AstrBot。

- 公网下载解析 DNS 后连接固定的已验证公网 IP，逐个检查重定向，TLS 仍校验原始主机。
- Atom 优先 alternate HTML link，禁止把 replies/comments feed 当文章。
- Feed 发布时间与社区提交时间分开处理；精度或时区不明时不伪造。
- 正文抽取保留原文，不用 RSS 摘要充当全文；去除菜单并保留图注。
- 私有来源配置采用显式主题规则，泛技术站不能整站自动归类成图形学或架构。
- 每篇只占一个主主题的每日额度，重跑不重置额度；缺新闻时输出真实缺口。
- SQLite 写事务前做在线快照并校验；文件原子落盘后登记状态，启动时对账孤立文件。
- 网络写入前落盘 submitted，未知结果先远端对账，禁止盲目重传。

## 部署和秘密

应用仅在本机 Docker 运行。实际宿主机数据根目录由私有配置指定，绑定 /data。
配置只读挂载；容器临时目录任务结束清理，异常遗留由下轮持锁后回收。
镜像仅白名单复制代码，不含来源名单、主题、凭据、原文或历史参考资料。

AstrBot 保持现有部署。其数据库写入前仍需服务端快照；本地数据库备份不能替代。
使用专用受限 SSH 入口访问原有服务，密钥只能调用指定知识库的 API/备份，不能执行任意命令或转发端口。
该入口是既有知识库的备份接入辅助程序，不是远程部署 NyaaNews。

## 验证口径

此前 33 篇原型验证只覆盖 RSS、正文下载和落盘；没有目标日过滤，
也有宽泛来源导致的错误分类，不能写成生产批处理已经验收。
历史原件保留在私有 .ref/；产品以日期、主题和正文校验后的结果验收。
满额不是每天成功的条件，允许没有新闻，但不允许拿旧文或无关文补数。
