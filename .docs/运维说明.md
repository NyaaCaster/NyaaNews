# NyaaNews 运行与维护

## 本机启动与检查

在仓库目录执行，先根据 config/ 示例创建被忽略的 .env/ 配置，并创建 HOST_DATA_DIR 指向的宿主机目录。
数据根目录必须映射到 /data；容器不会在挂载丢失时回退写容器层。

```console
python rebuild.py
docker compose --env-file .env/runtime.env up -d
docker exec nyaanews python -m nyaanews.cli check
docker exec nyaanews python -m nyaanews.cli status
docker logs --tail 50 nyaanews
```

rebuild.py 仅构建，不发布、不启动。重新构建后再执行 compose up -d 以更新运行容器。
停止服务使用同一 env-file 执行 docker compose down；绑定的数据目录不会被删除。
服务不开放 HTTP 端口，也不挂载 Docker socket。

## 日期、调度与失败处理

默认 cron 为北京时间每天 08:00，采集前一自然日。需要宿主机及 Docker Desktop 持续运行。
启动不会自动补采关机期间漏掉的日期，可显式补采：

```console
docker exec nyaanews python -m nyaanews.cli run --date YYYY-MM-DD
docker exec nyaanews python -m nyaanews.cli run --date YYYY-MM-DD --no-sync
docker exec nyaanews python -m nyaanews.cli sync
```

退出码 0 表示批次完成，2 表示部分来源、原文或同步失败，1 表示无法完成命令。
重复运行保持已占用的日额度，并按 URL/canonical/正文哈希去重。
来源 429/网络失败按源退避；修改订阅 URL 后不会沿用旧地址的退避与缓存。
正文抓取失败保留 deferred，成功来源的其他新闻照常归档。
unknown 提交先核对远端文档及所有块；无法判定的请求不会盲目重发。
V1 不提供绕过 unknown 的自动重置命令，需要维护人员核实任务/文档后处理状态。

/data/state/last-run.json 与 /data/logs/ 保存每轮结果；/data/state/scheduler.json 保存真实调度时间和退出码。
健康检查关注 cron 存活、挂载与 27 小时内的调度记录；正常结束的 partial 批次仍算调度存活，业务失败须查逐轮日志。
因此 healthy 不代表所有新闻候选或来源全部成功。

## 现有 AstrBot 的网关安装

新安装默认关闭 SYNC_ENABLED；完成以下管理员配置后再开启。
采集器仍只在本机运行，网关是既有知识库的 SSH 访问和备份辅助入口。

1. 在 AstrBot 现有挂载盘数据目录的同级 nyaanews-gateway/ 放置 ops/kb_gateway.py，并命名 gateway.py。
2. 在同目录创建私有 policy.json，字段如下；base 为服务端回环 API，kb_id 为唯一目标库，data 为现有 AstrBot 数据目录，mount 为实际独立挂载盘。
3. 生成专用 SSH key，向目标账号 authorized_keys 添加 restrict 与 command 限制；command 仅运行 python3 gateway.py policy.json。网关及策略仅允许管理员写入。
4. 通过已认证的管理员会话核对主机公钥，写入私有 .env/ssh/known_hosts；不要以关闭校验代替配置。
5. 配置 GATEWAY_*、ASTRBOT_USERNAME、ASTRBOT_PASSWORD、ASTRBOT_KB_NAME 并启用同步。容器只挂载专用 key，启动后复制到 tmpfs 并设置 0600。

```json
{
  "base": "<ASTRBOT_LOOPBACK_URL>",
  "kb_id": "<TARGET_KB_ID>",
  "data": "<ASTRBOT_DATA_DIRECTORY>",
  "mount": "<MOUNTED_DATA_ROOT>"
}
```

网关限制库列表、文档操作与检索目标，只允许导入/删除 nyaanews- 前缀文档，并持久记录其创建任务的归属。
网关会在 mount/backups/astrbot/deployments/ 下备份 kb.db、目标库 doc.db、文件与索引，校验哈希及 SQLite quick_check。
备份盘未挂载或备份失败时拒绝写入。备份是单库文件快照，不保证整个向量索引跨文件原子恢复。
更新 gateway.py 时保留 policy.json 与 tasks.json，避免丢失正在轮询任务的归属记录。

SSH 默认直连。如 Docker/VPN 环境需要 SOCKS5，可在私有配置设置 GATEWAY_SOCKS_HOST/PORT；GATEWAY_SOCKS_CONTAINER_ONLY=1 只在容器内使用代理。
代理不改变 SSH 目标地址与严格的主机密钥验证。代理必须可从容器访问，服务不可用时同步失败会被记录。

## 数据保护与清理

正式原文、SQLite 状态、逐轮日志和保护备份都在外部盘；不能将它们当作测试残留删除。
任何数据库维护写操作前先备份；不要直接编辑运行中的数据库或删除 unknown 状态。
任务 finally 清理工作目录，后续任务持锁后回收异常遗留；SSH 专用 key 在 tmpfs 中维持运行所需的生命周期。
临时测试文档定向删除，合成测试使用独立临时目录。备份和历史记录不自动删除，需另定容量保留策略。
不把私人主题、订阅、凭据、参考原件或原文复制进 Git。

## 来源级正文 HTTP 兼容模式（0.1.1）

来源配置可设置 article_http_profile，合法值为 standard（默认）或 chrome。
chrome 使用 curl-cffi 的浏览器兼容 HTTP/TLS 模式；仍为 Python 非交互请求，不安装或运行 Chromium。
仅对验证需要的来源启用；RSS/Atom 发现仍走原有解析路径，不改变主题、时间窗和限额。
连接固定到本机校验过的公网 IP，证书验证保持开启，不继承隐式 HTTP 代理，并逐跳检查重定向及 HTTPS 降级。
响应回调限制大小与时间，不将验证页或订阅摘要当成正文。
失败日志中的 browser_challenge 表示服务端返回浏览器验证，http_status 保留真实状态码；普通 HTTP 错误同样保留状态码。
兼容模式不保证任意站点始终可访问，仍失败时保留 deferred，不能关闭证书校验或拿摘要冒充原文。
